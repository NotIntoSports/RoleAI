# RAG 检索离线评测报告

> 生成：2026-09-30，lane-C（C44）。全部数字来自本机实际运行，可一键复现。

## 方法

- 语料：`src-tauri/tests/fixtures/rag/documents.json` —— 虚构产品「云舟协作平台」的资料 10 篇（每篇约 350–450 字，语料规模刻意保持小型以便复现）。**内容全部虚构**，仅用于评测。
- 题集：`questions.jsonl` —— 50 个自然语言问题，每题标注金标资料（docId）与金标段落片段（goldSnippet）。
- 三种检索方式：
  1. **keyword**：生产 FTS5 关键词路径（trigram 分词 + 停用词切分 + AND 短语）；
  2. **vector**：字符 bigram 哈希嵌入替身（128 维、L2 归一化）——**只评检索机制，不代表真实 Embedding 的语义能力**；
  3. **hybrid**：关键词 + 向量替身的 RRF 混合（生产路径）。
- 指标口径：Recall@1/3/5 与 MRR。「块级」要求命中块包含金标片段；「文档级」要求命中块来自金标资料。
- 运行器：`src-tauri/examples/eval_rag.rs`。复现：

```powershell
cargo run --manifest-path src-tauri/Cargo.toml --release --example eval_rag
# 结果：target/rag-results.json
```

## 结果（50 题）

| 模式 | R@1 | R@3 | R@5 | MRR |
| --- | ---: | ---: | ---: | ---: |
| keyword（块级 / 文档级） | 2% | 2% | 2% | 0.02 |
| vector 替身（块级 / 文档级） | **62%** | **70%** | **84%** | 0.69 |
| hybrid（块级 / 文档级） | **62%** | **70%** | **84%** | 0.69 |

## 结论与发现

1. **自然语言整句提问下，关键词路径几乎完全失效**（2%）。根因：FTS5 trigram 分词 + 停用词切分后的 AND 短语要求每个子串逐字出现，整句问法与资料原文的措辞差异就会导致零命中。这不是缺陷修复项，而是路径定位——关键词路径服务的是"精确术语短查询"（如贴报错码），自然语言问句必须靠向量一路。
2. **向量替身达到 R@5 84% / MRR 0.69**：替身本质是"抗分词的字符级词汇匹配"，它能拿到这个数字说明**检索机制（sqlite-vec + RRF 融合 + 相邻块合并）工作正常**；替换为真实 Embedding 后语义泛化只会更好——但这一点要等在线评测验证，本报告不做任何推断性数字。
3. **hybrid 与 vector 完全一致**：在替身设置下关键词一路几乎没有贡献候选，RRF 退化为单路。这与结论 1 自洽；真实 Embedding 下两路互补性预计会恢复（待在线评测验证）。
4. 评测把检索黑盒打穿了一次：块包含金标片段的严格口径 + 跨块相邻合并的生产行为都按真实路径执行（未绕过任何生产代码）。

## 局限性（诚实清单）

- **bigram 哈希替身不是语义 Embedding**：它对同义改写无能为力，84% 的 R@5 全部来自字面重叠。真实 Embedding 的召回质量、以及在线模式（真实 Key）评测，需用户配置后另跑（`eval_rag` 预留了在线路径，默认不跑）。
- 语料只有 10 篇 / 50 题，规模小；置信区间宽，只支持数量级结论与机制验证。
- 金标片段以子串包含判定命中，块边界若恰好把片段切开会导致漏计（评测语料的片段都取自块内完整句子，已尽量规避）。
- 未评测多跳/聚合类问题（需要跨段落推理的检索），当前检索接口的定位是单段事实问答。
