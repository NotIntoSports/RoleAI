# 0002 — 本地优先 + 凭据管理器，不做账号系统

- 状态：已采纳
- 日期：2026-08（随多进程收敛一起确立）

## 背景

旧架构有完整的登录、用户管理与令牌体系（Go Control API 签发、客户端安全存储、心跳与强制登出）。收敛后必须回答：个人桌面工具要不要账号？API Key 放哪？

## 选项

1. **自建账号体系 + 云端配置同步**——要养服务器、管凭据、写隐私政策，与"本地优先"矛盾。
2. **明文配置文件存 Key**——最简单，但配置文件一备份就泄密。
3. **本地优先 + 操作系统凭据管理器**：无账号，配置文件存本机；API Key 存 Windows Credential Manager，配置与界面里只有密钥引用。

## 决策

选项 3。Key 经 `keyring` crate 写入 Credential Manager（DPAPI CurrentUser），内存副本 `zeroize` 清零；非 Windows 平台用内存实现便于测试。威胁模型的边界在 [SECURITY.md](../../SECURITY.md) 与[安全设计](../security.md)中明示：同一 Windows 用户下的恶意进程不在防御范围内。

## 后果

- 好处：没有服务器就没有服务器泄露；配置文件可以随便备份；离线可用（除模型请求外）。
- 代价：换机器要重新录 Key（可接受——Key 本来就该逐台录入）；跨平台要把 keyring 后端换成各 OS 等价物。
- 边界：不做静态加密磁盘数据，依赖系统盘加密（BitLocker）。
