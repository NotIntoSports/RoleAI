# 0008 — 自写有界重试，不引入重试库

- 状态：已采纳
- 日期：2026-09-29（候选对比核实了 backon 的许可证、维护活跃度、blocking 支持与依赖树）

## 背景

级联线路（ASR / LLM / TTS）的瞬时失败需要重试：连接错误与 HTTP 429/502/503/504 是典型的瞬时故障。Rust 生态的现成选择是 backon 这类重试库。

## 调研结论

backon 本身无可指摘：Apache-2.0、活跃维护、官方 blocking 支持、依赖极小。**决策基于性价比而非库的缺陷**：

- 需求只是 2 次固定间隔（300 ms / 900 ms）重试，库能替代的只有"循环 + sleep + 计数"约 10~15 行骨架；
- 真正的领域逻辑——可重试判定（连接错误 + 特定状态码）、"流式路径一旦吐字不可重试"、重试间隙检查取消令牌——任何库都得自己写；
- 三处调用（ASR/LLM/TTS）收敛在同一个 `send()` 单点，自写版本的改动集中、易于离线测试与审计。

## 决策

自写有界重试（≤30 行），不新增依赖。明确不重试：超时（单次已 30 秒，重试成倍拉长等待）、401/403、其余 4xx、响应超限与解析失败。

## 后果

- 好处：依赖树零增长；重试语义与取消语义集中在一处可读的函数里。
- 代价：将来如果重试策略复杂化（jitter、Retry-After 透传、指数退避），应重新评估引入库——这个"重新评估的触发条件"写在了决策记录里。
