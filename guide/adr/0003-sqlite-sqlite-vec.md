# 0003 — SQLite + sqlite-vec，不引入独立向量数据库

- 状态：已采纳
- 日期：2026-09-06 前后（随知识库落地确立；Embedding 供应商决策同日记录于 `docs/dependency-decisions.md`）

## 背景

知识库需要向量检索。常见的"专业"做法是额外跑一个向量数据库（Milvus、Qdrant、pgvector + Postgres……），但对单机桌面应用，这意味着多一个要安装、要启动、要备份的服务。

## 选项

1. **独立向量数据库 / Postgres + pgvector**——检索能力强，但要用户装数据库服务。
2. **纯内存向量检索**——无持久化，重启全量重算。
3. **SQLite + sqlite-vec 扩展**：向量走 vec0 虚拟表，关键词走 FTS5，全部在同一个数据库文件里。

## 决策

选项 3。`sqlite-vec` 0.1.9 以 Rusqlite 扩展形式注册；资料、分块、向量、会话记录同库；检索用 FTS5 与向量两路候选 + 倒数排序融合（RRF，k=60），见[知识库文档](../knowledge-base.md)。

## 后果

- 好处：用户无感知的部署（一个 .db 文件）；备份 = 复制一个文件（在线备份 API）；迁移 = SQLite 迁移脚本。
- 代价：sqlite-vec 是较新的扩展（钉版 0.1.9 并有版本测试钉住）；百万级向量以上不是它的战场——本项目的量级（个人资料库，单文档 ≤500 块）远够。
- 取舍记录：Embedding 本身也走 OpenAI 兼容接口、可选供应商或自定义 URL，不为向量检索新增 SDK 依赖。
