# 0006 — 用 C# AudioBridge 子进程采集会议音频

- 状态：已采纳
- 日期：2026-08-10（设计）至今持续演进

## 背景

会议助手要对"指定会议进程"做本机回环音频采集（WASAPI process loopback），并把 AI 播报输出到指定设备（如虚拟声卡）。Rust 生态对 WASAPI loopback 的现成绑定不成熟，自己写 COM 层风险高。

## 选项

1. **Rust 直接做 WASAPI 进程环回**——依赖不成熟，COM 安全初始化、设备变更、会话枚举都是坑。
2. **C# 子进程 + NAudio.Wasapi**：NAudio 是 Windows 音频事实标准库（MIT），进程隔离天然防崩溃传染。
3. **让用户手动设置立体声混音**——体验差且不可靠。

## 决策

选项 2。`native/AudioBridge` 是一个 .NET 10 控制台程序（复用 MIT 许可的 NAudio.Wasapi 3.0.0-preview.20），以 stdin/stdout 帧协议与主进程通信：

- `--pid <PID>`：对白名单内的会议进程做回环采集；
- `--play-stream <设备> <采样率>`：常驻流式播放，帧类型 audio / clear（打断清空）/ drain（播净回执）；
- 发布产物自带 .NET 运行时，用户无需安装 SDK；约 100 MB 的发布产物不入 git，构建机先发布。

关键约束：不改系统默认设备、音频不落盘、会议进程白名单精确匹配可执行文件名。

## 后果

- 好处：崩溃隔离（音频子进程挂了主进程能感知并重启）；NAudio 的设备枚举与缓冲管理久经考验；打断清空由一帧消息完成。
- 代价：构建链多一个 .NET SDK 依赖；安装包大；主进程要管理子进程生命周期与 stdout 协议解析（有测试覆盖）。
